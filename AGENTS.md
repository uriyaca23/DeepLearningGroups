# DeepLearningGroups project instructions

These instructions apply to the entire repository.

Before doing any homework work, read these files completely:

1. `HOMEWORK_STYLE_GUIDE.md` — the authoritative, stable collaboration,
   writing, Word, RTL, and verification contract.
2. `PROJECT_STATE.md` — the current, changeable progress record.
3. `style/homework_style_contract.json` — the exact machine-enforced Word
   values and approved exceptions.

The latest explicit user instruction has highest priority. Otherwise,
`HOMEWORK_STYLE_GUIDE.md` overrides the current DOCX, prior agent memory,
generic Word defaults, and tool defaults. If the guide, the state file, an
exemplar, or a user instruction appears to conflict, stop and ask the user
instead of guessing.

Non-negotiable:

- Do not independently solve new homework content.
- Do not write a new answer into `HW4-Solution.docx` before explicit approval
  of the formal answer.
- Treat `old/HW4-Solution.pre-q3a-20260724-230819.docx` as the last accepted
  visual baseline through Question 2(e). `HW4-Solution.docx` is the current
  accepted and visually approved checkpoint through Question 3(b); new work
  begins with Question 3(c).
- Build DOCX edits on a candidate copy by cloning accepted document elements;
  never start from a blank document or apply generic Word formatting.
- Run the structural audit and Word render gates specified in
  `HOMEWORK_STYLE_GUIDE.md` before promoting a candidate.
- Do not call a DOCX insertion, audit, visual review, or publication approved
  unless that specific gate actually passed.
- Keep superseded DOCX files in `old/`, not in the main folder.
- Never use, inspect, or modify `LocationPipeline` for this project.

Do not change `HOMEWORK_STYLE_GUIDE.md` or its mechanical contract unless the
user explicitly approves the change.
